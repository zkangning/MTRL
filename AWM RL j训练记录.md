# AWM RL 环境构建

### 问题 1：`_wait_for_server` 只检查 TCP 端口，不验证 MCP 就绪

当前的 `_wait_for_server` 只做 TCP socket 连接检查，但 TCP 端口打开不代表 FastAPI+MCP 已经完全初始化。uvicorn 可能已经绑定了端口但 MCP 路由尚未 mount 完成。

### 问题 2：`isolated_mcp_env` 在多线程中不安全

`isolated_mcp_env()` 是一个 context manager，它**直接修改 `os.environ`**（删除大量环境变量，然后恢复）。当 64 个线程并行调用 `from_dict()` → `_start_server()` → `mcp_manager.initialize()` 时，多个线程同时调用 `isolated_mcp_env()` 会互相干扰 — 线程 A 清空环境变量时，线程 B 可能正在启动 subprocess，导致子进程缺少必要的环境变量。

### 问题 3：每次 `call_tool`/`list_tools` 都重建 MCP 连接

看 `AWMMCPConnectionManager.call_tool()`（第 100 行），每次调用都 `async with self._app.run()` + `async with self._agent`，完全重新建立连接。这个设计不持久化连接，效率很低且容易失败。
